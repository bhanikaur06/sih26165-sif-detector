# oil_validation.csv — how it was built

174 hand-written Indian-oilfield-style unsafe-act / unsafe-condition / near-miss
reports, generated by `data/scripts/build_oil_validation.py`. This is the
honest domain-transfer check: a model trained only on MSHA (US mining)
narratives is evaluated here against report style, terminology, and incident
types typical of an Indian onshore oilfield operator (rig floor, wellhead,
GGS/CTF, flowlines, tank farms) — never merged into the MSHA train/val/test
split.

## Columns

Same columns as `msha_labeled.csv`, including the four grouping columns
(`mine_id`, `operator_name`, `activity`, `subunit`). Those carry invented but
internally consistent oilfield values — installations like `GGS-02`,
`RIG-07`, `WELLPAD-14`, `CTF-01` under subunits like `DRILLING RIG` and
`PRODUCTION INSTALLATION` — so the dashboard can be demoed against Indian
oilfield sites rather than US mine names. They are illustrative, not real
assets, and no metric in the write-up should be attributed to a real site.

Two columns are used differently here since this file has no MSHA origin:

- `source_code` — not an MSHA code. It's an internal category tag showing
  which IOGP Life-Saving Rule (or, for the negative class, which routine/
  non-SIF category) the report was written to represent. Kept in-schema
  instead of adding a new column, so this file matches the root contract
  exactly.
- `split` — always `"oil_validation"`, distinct from `train`/`val`/`test` on
  purpose, so it can't be silently merged into the MSHA split by a script
  that just filters on `split`.

## Label rationale

`sif_label = 1` rows were written to represent a violation/near-miss against
one of the 9 IOGP Life-Saving Rules (`LSR_*` codes: working at height, line
of fire, confined space, energy isolation, hot work, lifting operations,
driving, bypassing safety controls, permit to work) plus a general gas/leak
category (`LSR_GAS`) — high actual-or-potential-severity events, mirroring
how `sif_label` was defined for the MSHA side in `LABEL_MAPPING.md`.

`sif_label = 0` rows (`NONSIF_*` codes) are routine housekeeping,
minor-PPE, ergonomics, and administrative/documentation findings — real
categories that show up constantly in UA/UC report logs but carry no
realistic fatality/serious-injury potential. These exist so the validation
set actually tests discrimination, not just "does the model say yes to
anything mentioning a rig."

## Class balance

102 positive / 72 negative (59% / 41%) — skewed positive on purpose, since
near-miss/UA-UC logs in practice contain a lot of genuinely reportable
findings, but not so skewed that precision/recall on the negative class
can't be measured meaningfully.

## Regenerating / extending

Re-run `python3 data/scripts/build_oil_validation.py` from the repo root
after editing the narrative lists in that file. It asserts uniqueness of
`doc_id` and `narrative` and a 150-200 total row count before writing.
